# Webflow Recovery — what `/webflow` and `/rs` actually contain

**Date:** 2026-09-11 · **Scope:** Phase 3 of the three-source brief.
**Method:** byte-level comparison of the three HTML captures with URLs normalised, MD5
hashing of every binary against `Front_end_website/public/`, and live verification of
every font endpoint.

---

## 1. Verdict up front

> **`/webflow` contains nothing that is not already in the React project.**
> **`/rs` is the valuable source — but for its *assets*, not its HTML.**

Do **not** pick the source by file size. The three HTML files are within 800 bytes of
each other and, once URLs are normalised, they are **the same document**.

| Capture | Bytes | Scripts | `class=` | `<img>` | `srcset` | Verdict |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| `webflow/webflow/index.html` | 222 807 | 16 | 1410 | 41 | 28 | Pristine CDN URLs. **Duplicate.** |
| `rs/rs/www.era-residence.com/index.html` | 223 124 | 16 | 1410 | 41 | 28 | Same DOM, HTTrack-rewritten relative URLs |
| `Front_end_website/reference-download/html/index.html` | 223 581 | 16 | 1410 | 41 | 28 | Already in the repo. **Identical to `/webflow`.** |

Measured similarity after stripping `src`/`href`/`srcset`:

- `webflow` vs `reference-download` → **1.00000** (only difference: character encoding of
  an ASCII-art `console.log` banner in a comment)
- `webflow` vs `rs` → **0.99899** (only difference: HTTrack's mirror header and relative
  URL rewrites)

All three carry the same Webflow build stamp: `Last Published: Mon Jul 20 2026 01:18:11 GMT`.

**Consequence:** `/webflow` can be ignored for the rest of this project. Every task that
would have used it is already served by `reference-download/html/index.html`.

## 4. Fonts — the exact references are publicly reachable

Production declares three families:

```css
--_fonts---font-display: ambroise-francois-std, sans-serif   /* Adobe Typekit */
--_fonts---font-accent:  sloop-script-three, sans-serif       /* Adobe Typekit */
--_fonts---font-body:    "Maison Neue Extended", Arial, …     /* self-hosted woff2 */
```

**Verified live, this session:**

| Endpoint | Status | Bytes |
| --- | --- | ---: |
| `https://use.typekit.net/pig8glj.css` | **200** | serves both `@font-face` blocks in the clear |
| `…/af/02a0c4/0000000000000000773598f9/31/l` (ambroise-francois-std) | **200** | 20 004 — no `Referer` check; works from `localhost` |
| `…/af/ceca40/00000000000000007758dac7/31/l` (sloop-script-three) | **200** | — |
| `…/6a06a699…_MaisonNeueExt-Book.woff2` | **200** | 45 824 — **byte-identical to `public/fonts/maisonneueext-book.woff2`** |
| `…/6a06a6b2…_MaisonNeueExt-Bold.woff2` | **200** | 47 092 — **byte-identical to `public/fonts/maisonneueext-bold.woff2`** |

So: the body font is already exact, and **the display and accent faces are obtainable by
reference** — the kit stylesheet is the same one production links. The React project
currently substitutes **Bodoni Moda** and **Pinyon Script** and compensates with a
`transform: scaleX()` squeeze. See `comparison-analysis.md` §D1 for why that one
substitution is upstream of at least five separate visual defects.

*Licensing note, stated once:* linking the Adobe kit is what production does, but Adobe's
Typekit terms scope a kit to its registered domains. Loading `pig8glj` from another origin
is a licensing question for the site owner, not a technical blocker. It is your call; the
technical path is clear either way.
